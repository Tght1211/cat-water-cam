# Web UI 全面重设计（PC 优先 · 侧边栏多页 · 饮水机核心交互）

日期：2026-07-05
状态：已定稿（用户以 /goal 指令授权自主设计并实现）

## 背景与目标

旧版网页是「顶部标签 + 一页往下拉很长」的粉彩风单页，用户反馈：不够先进、
功能模块分类奇怪、喝水记录里混着「没喝/待判定」的视频、饮水机板块不够核心、
动画太少。本次**完整重写 `web.py` 的 `INDEX_HTML`**（后端 API 零改动），目标：

1. **PC 优先**的现代仪表盘布局：左侧固定侧边栏导航，每页内容聚焦、不做超长滚动。
2. **信息架构重组**：普通用户只看「监控 + 记录 + 趋势 + 饮水机」；标注/训练/模型
   全部收进「实验室」。
3. **喝水记录页只展示已确认喝水的视频**（`labels[n] === true`）；未判定与「没喝」
   的段只出现在实验室·标注工作台。
4. **饮水机是核心交互板块**：独立成页、重点打磨水箱动画与操作流。
5. **动画丰富**：全部手写 CSS/JS（不引外部 CDN，恪守「画面/页面只在本机与局域网」
   的纯本地原则），尊重 `prefers-reduced-motion`。

## 设计语言

- **水主题「aqua glass」**：主色青蓝（水），辅色暖珊瑚（猫），深色 = 深海夜色
  （`prefers-color-scheme` 双主题），玻璃拟态卡片（半透明 + backdrop blur）、
  柔和光晕、圆角大卡。
- **排版**：系统字体栈；统计数字特大号 + `tabular-nums`；中文 UI 文案保持现有口吻。
- **微动效清单**：
  - 侧边栏激活指示条滑动（spring 缓动）；页面切换卡片级联入场（`--i` 延迟）。
  - 所有大数字 count-up；实时画面「在线」呼吸点。
  - 视频卡懒加载骨架 shimmer；hover 抬升 + 封面缩放。
  - 灯箱（视频播放 / 实时画面全屏）：模糊背景、Esc 关闭。
  - toast 通知替代 `alert`；自定义模态替代 `prompt/confirm`。
  - 全局背景两团缓慢漂移的柔光 blob（`prefers-reduced-motion` 下静止）。

## 饮水机页（核心）

- **大水箱 SVG**（约 260px）：三层波浪不同速横移形成视差、随机气泡上升、
  玻璃高光；水位变化用 `transform: translateY` 过渡（0.9s spring）。
  水色随水位：正常青蓝渐变 → `<40%` 琥珀 → 低于 `need_water` 阈值红橙 + 外发光警示。
- **水位数字**：百分比 count-up；副行「约 X / Y ml」。
- **滤芯**：SVG 环形进度（剩余天数/周期），超期变红 + 抖动提示徽标。
- **加满水**：自定义模态——预设芯片（500/1000/1500/2000ml，记住上次值）+
  滑杆 + 数字输入；确认后水位动画升到 100% + 顶部落水滴动画 + toast。
- **换滤芯 / 周期设置**：轻量确认模态 / 步进器模态。
- **未初始化态**（`has_refill=false`）：空水箱 + 引导文案 + 大按钮「加满水」。
- 总览页放**速览小水箱**（同一 SVG 组件缩小复用），显示 % 与告警点，点击跳转。

## 技术决策

- 仍是 `web.py` 单文件 `INDEX_HTML`（vanilla JS，无框架、无 CDN）；页面切换 =
  纯前端 show/hide + `location.hash` 路由（`#/dispenser` 等），懒加载各页数据。
- 后端 API 不动；喝水记录页的「只看已确认」在前端用 `labels` 过滤。
- 保留既有安全/行为约束：`fb()` 的 DOM 局部更新限定标注工作台容器；
  内联 `onclick` 嵌 `JSON.stringify(name)` 时属性用单引号；下载含/去声开关沿用
  `?audio=0`。
- 测试不断言 HTML 内容，重写不影响 `tests/test_web.py`；验证靠
  `python -m catcam.demo` + Playwright 截图（浅/深色、各页面）。

## 不做（YAGNI）

- 不加手动主题切换（跟随系统即可）。
- 不做移动端深度适配（PC 优先；仅保证窄屏不烂：侧边栏折叠成图标条）。
- 不改后端口径/新增 API。
