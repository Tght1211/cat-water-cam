# 专属小猫模型与饮水闭环

本轮目标是让用户从自己的摄像头、饮水机、背景和小猫数据出发，训练并持续纠错，而不是依靠内置模型的一次验证准确率。

## 查到的问题

- 新克隆不含用户数据；本机找到的旧项目仅有一条标注。目前没有足够的用户数据证明识别准确率提升。
- 原 S3D 输入把整个会话稀疏压成16帧，舔水动作容易丢失。旧版抽帧保留供内置分类头兼容；新训练使用连续两秒窗口。
- 随机留出可能缺少正样本；没有独立调阈值与测试隔离，评估结果也未随版本持久化。
- 视频训练没有更新标注训练状态；训练后需另行手动启用，旧录像仍显示旧预测，容易造成训练无效的观感。
- 改标注后旧类别抽帧没有删除；原视频被展示列表裁剪后只能依赖已有特征，无法继续主干微调。
- 水量校准把每次补水当作上一箱已经用完；没有剩余/损耗反馈，平均每次饮水量会被高估。
- 原趋势页把零记录描述为“今天没喝”，缺少监控完整度和弱光停用状态。
- 外部标注提示词把看不清舔水当成负样本；模型池的多轮失败/重试未受共享预算限制。

## 当前工作流

1. 专属模型 → 模型训练 → 设置饮水区域，覆盖水盆、猫嘴及动作区域。
2. 本地检测持续采集候选，人工区分“喝水”和“靠近但没喝”。可选外部老师辅助生成高把握标注，不确定项保留人工复核。
3. 选择训练方式：
   - **S3D 连续动作分类头**：三个连续两秒窗口，区域裁剪后提特征，均值与最大值聚合；训练标准化、正类加权并带正则化的分类头。
   - **S3D 主干微调**：默认8轮，冻结前段，只更新末段特征层；会话使用多实例监督，正会话不等于每个靠近/离开窗口都标成喝水。按验证损失保存主干，再训练分类头。
   - **VideoMAE**：可选 Hugging Face 主干 `MCG-NJU/videomae-base-finetuned-kinetics`；需安装 `.[videomae]` 并下载权重。目前网络访问 Hugging Face 失败，未完成该权重在本机的真实推理验证；默认 S3D 已跑通。
4. 优先按日期隔离训练/验证/测试；只有一个日期时使用分层留出并提示局限。验证集调阈值，测试集独立评估。
5. 后续保留测试录像，初期小留出集仅用从未参与训练的新视频扩充；可在新独立日期足够时升级评估，退役测试录像不拿去训练。
6. 成长记录保存漏判、误判、召回、精确率、划分和新旧版本在共同留出片段上的对比。退步会真实显示，不自动替换原模型。
7. 勾选完成后启用时，新模型可直接开始预测，并重新评估已有录像。当前自动判定版本不会被评估不足的新版本替换。
8. 用户可在「复核与纠错 → 自动确认设置」启用两端高分自动确认：喝水得分≥99.5%或≤0.5%自动计为喝水/没喝，中间项保留复核。该偏好在测试模式下也生效，可对已有录像重新评估，不覆盖人工/外部标注。机器结论不作训练真值，得分不是正确率。
9. 完整自动判定模式要求按日期独立评估、测试每类至少10段、喝水召回和精确率均至少80%，且无重复视频等评估警告。阈值附近±0.15的得分保留待复核。该门槛不保证新环境的准确率，仍需抽查。

训练至少每类4段是运行下限，不是准确率保证。真实喝水、凑近没喝、不同日期和可用弱光样本都需要覆盖。

## 数据和版本

- 标注原视频归档到 `data/training/videos/`，展示列表裁剪不删除训练档案。
- 特征缓存按主干、区域和微调权重隔离，校验源视频大小/修改时间和特征维度；修改分类阈值不会污染缓存。
- 版本报告保存在模型注册表；训练结束按标签快照更新状态，训练过程中发生的纠错不会被错误标为已训练。
- 人工优先于外部和本地模型；外部调用过程中发生的人工纠错也有事务保护。
- 实战命中统计排除当前模型的训练/验证录像，避免把背过的样本算作新实战效果。

## 水量、周期和健康

- 首次填写加水后的总量。确认一次喝水就记录一次，初期按配置的每次用量估算今日摄水量和剩余水量，界面明确显示估值。
- 记录实测水位可校正估算起点。
- **本轮没水了 → 反馈校准**：填写剩余量及已知蒸发、泼洒等损耗；平台保存本轮时间段和有效消耗量。尚有待复核录像的周期不加入校准池。
- 周期平均用量 = 有效总消耗 / 当前确认的喝水次数；以后改正误判会重新计算历史周期，不沿用错误的旧次数。
- 喝水时长初期按录像长度的80%估算，独立保存来源；人工填写真实舔水秒数时优先使用人工记录。周期内每次都有人工或估算时长时，可换算毫升/秒，并标明校准是否用过估算时长；缺少时长则按每次平均用量估计。当前尚未自动定位喝水动作起止。
- 最近有效周期的消耗速度用于估计到低水位和用完的天数；缺少有效周期/水位差时不虚构预测。
- 健康页结合有效监控时长、待复核记录、历史完整监控日和历史同时段的次数/摄水估值变化。食物中的水、其他水源及其他宠物不在单个摄像头统计范围内。
- 预览、录像和识别均使用摄像头原始画面，关闭弱光增强及轮廓候选采集。饮水区域过暗或缺少细节时停止录像并清空预录缓存，不把缺失监控当作没喝。新增补光后，画质可用时继续正常检测。
- 页面支持自动/深色/浅色外观，本浏览器记住选择；自动模式在20:00至07:00或系统深色时使用深色。

## 补光后的夜间行为

用户在饮水机旁加灯后，已停用软件弱光增强和轮廓候选采集。全流程使用原始画面，整幅画面或饮水区域亮度低于50、检测不到猫或细节不足时不触发新的录像；若录制过程中画质变得不可用，立即结束已保存的有效画面，清空预录缓存，避免把不可用画面带入下一段录像。既有弱光候选的人工复核限制保留，原录像和人工标注不受修改。

页面的深色外观独立保留，不改变摄像头画面。

按已保存的弱光候选标记及抽帧亮度清理211段弱光录像，连同训练副本、抽帧、特征缓存和对应事件/标注删除；保留11段光线充足的录像。清理明细仅保存文件名与数量于被Git忽略的 `data/maintenance/`，不保留被删视频。后续全局暗场停止记录（`record_at_night=false`，该选项按画面亮度判定，不按时钟），饮水区域亮度门槛至少50，补光达到门槛后恢复。

## 用户饮水机出水参考

新增 FlowMonitor，本地每秒最多比对两次出水口原始画面。用户界面可调整监测区域，并在关闭/开启饮水机后各点击一次采集参考。参考截图与区域独立保存在用户的数据目录，不内置本用户的画面，也不使用外部 API。当前部署已保存用户明确标注的停止出水截图。稳定比对约 20 秒才自动转换状态，明显不同或两个参考不可区分则待确认。弱光、猫咪遮挡及离线不解除已有故障提示；提示独立于估算剩余水量，无法直接判定故障原因。

这是可解释的参考校准，不是训练好的通用水流模型；真实正常出水的自动识别还需要用户恢复设备后采集正常参考验证。新增测试覆盖稳定观察、摄像头中断、遮挡、弱光、参考混淆、重启警报保留、区域重设和 API 校准。

## 邮件通知与异常原因

原邮件设置关闭且没有 SMTP 凭据；新增侧栏配置入口、测试邮件与状态接口，密码不返回。后台十秒轮询确认标签，持久化队列按录像去重，不再受每十分钟一封的限流影响，覆盖人工、机器和 AI 确认。发送失败递增间隔重试，发送前取消已纠正为没喝的记录。SSL/STARTTLS 均支持。每日 23:00 汇总，周日只生成周汇总，统计截至 23:00；重启后只补最近到期汇总，不追补全部离线日。首次开启从此后新确认记录开始通知。邮件发送需要用户填入 SMTP 授权码和邮箱；当前配置为空，未声称真实邮件投递已验证。

停水原因结合用户明确反馈的耗尽周期（新增剩余量、当轮加水总量字段），按加水体积调整历史周期中位数，再比较本轮经过时间。最近实测充足水位优先提示设备检查。此为规则估计，不宣称故障分类概率。历史记录缺少耗尽水位的周期不自动当作空箱。停水警报标识跨重启保存，避免同一持续故障反复通知。

## 分次加水、残水和提醒校准

新增加水账本与可累计周期。新加水接口使用 added_ml，可选 initial_remaining_ml，活动周期内不重置起点或喝水记录；剩余水估值从上次水位扣除已确认饮水消耗后再追加。初始残水未知标记 baseline_known=false，完整周期校准排除该轮，直到下一轮从实测残水建立已知基线。停水反馈必须在页面填写测量残水，不预填0；保存停止工作时的残水阈值。提醒阈值初始为空，用户观察红灯常亮并实测后采集，软件推算至少需要一轮有效周期。指示灯 ROI 用户自选，明确启用后才采样，观察稳定红色与重复明暗切换；异常光照、遮挡和离线保留未知，灯灭不证明出水。低水量邮件也经过相同数据门槛并持久化去重。

FlowMonitor 新增停止/恢复区间和提醒关闭记录，从旧状态日志迁移历史，参考比对允许3像素特征平移以适应轻微移动。当前部署保存用户明确标注的停止画面和恢复画面，继续使用用户选择的出水 ROI；实时接口已观察到 flowing、alert=false。用户已加的950 ml已入账，计划中的1050 ml未记录。UI提供水量与加水、提醒与设备、设备记录三个页签，并支持手机。

## 动作与实际饮水分别标注

labels 新增 action_drinking 和 outcome。is_drinking继续代表实际饮水统计，dry_lick表示有舔水动作但未喝到水（is_drinking=0, action_drinking=1）；no_action才是动作负样本。视频训练快照、帧类别、已训练版本跟踪及模型命中率改用动作真值，健康/用水校准/邮件仍使用实际饮水真值。人工纠正结果与原因可从每条记录修改，也可在复核工作台选择；人工标签优先级不变。测试验证干舔不产生摄水记录且仍为训练正样本，追加加水不丢事件，停水10%残水能反馈，恢复提醒跨重启持久化并可关闭。

补充：events记录 water_review 出水上下文，按录制时间与停止区间是否重叠判定。停水区间中的动作正预测不自动写为实际饮水，重新评估也遵守此门槛；动作预测仍用于命中率分析，人工确认优先。新增测试覆盖 gate/shadow 两种模式100%动作分也不误计饮水。

用户指出指示灯不在摄像头视野内：移除指示灯框选与视觉监测的界面入口，采集循环不再创建或运行 IndicatorMonitor。提醒设置强制关闭旧指示灯配置，水少由用户观察设备后手动确认实测水位，停水/恢复继续使用出水口监测。

首页今日时间线内嵌在主概览卡片顶部，取消独立底部卡片。饮水机概览改为整张储水卡片，水面高度跟随剩余比例，带波浪及上升气泡；展示估算水量、可用天数和滤芯剩余天数，缺少周期或更换记录时明确显示待校准/待记录。支持手机布局、键盘进入饮水机页面及减少动态效果偏好。浏览器验证时间线仅有一处、100%水位填满卡片、手机无横向溢出；JS语法、静态页面测试及diff检查通过。

修复暗背景误停录：原先饮水ROI画质合格后，全图亮度低于50仍会被record_at_night额外否决。采集与检测统一只用饮水ROI画质决定是否暂停，夜间标记也从ROI亮度产生；保持原始画面及低画质拒录。回归验证暗背景/明亮饮水区可用、亮背景/黑暗饮水区拒绝，相关15项测试通过。重启后实时接口观察到usable=true、status=normal。


## 饮水机与专属模型界面重设计

饮水机水量页分为储水概览、当前周期、实测/残水快捷操作、周期学习及出水监测；提醒页分为水少、停水残水、滤芯、邮件四个功能区域。设备记录按日期排列，支持加水/水位、周期/提醒、停水/恢复筛选。保留既有加水与周期接口；实测水位不再预填估值，防止估值被误保存成实测结果。出水校准展开状态在轮询后保留。
