# 猫咪喝水检测：速度、效果与无夜视方案

## 定位结论

本项目已经使用预训练模型识别猫。需要适配的是猫嘴接触水面时的动作，不能把“有猫”“在水碗旁停留”等同于“喝水”。通用检测模型也不一定认得特殊造型的饮水机，固定相机下应优先手动框定水碗区域。

旧流程存在几个具体问题：

- 每次抽 16 帧前，先把整段录像解码、转为 RGB 并放进内存；人工标注抽帧也会读完整段。
- 在线判断已经计算的 S3D 特征没有写入训练缓存，之后训练再次计算。
- 切换版本和每轮训练会创建新主干实例；device 参数并未用于模型/输入迁移。
- 训练状态只显示一个笼统进度，训练成功后也不会自动替换当前版本，用户难以知道时间花在哪里、新版是否已参与判断。
- 实战命中率把机器标签也当真值，过滤模式却不保存预测供后续人工对照。
- 夜间先增强后保存/识别，可能把黑暗噪声作为模型输入；零记录还被直接写成“今天还没喝水”。

内置模型的 519 段样本中，462 段是负例，全部猜没喝在这批样本上也有 89.0% 准确率。公布的验证 top1 是 89.1%；由于未提供完整验证分布，不能把这两个数直接当作同集比较，但足以说明 top1 单独不能证明饮水识别效果。

## 已落地的改进

1. **按需抽帧**：保留旧采样位置与颜色格式，只转换和保留目标帧，短视频补帧行为兼容。无帧数元数据时先做常量内存计数；人工抽帧共用该实现。
2. **在线/训练共享缓存**：在线判断立即保存特征；人工确认后训练直接复用。共享一个主干实例，用锁串行化推理以控制内存、避免并发 hook 串数据；特征输出直接取主干池化结果。
3. **实际使用计算设备**：默认自动选择 CUDA / MPS / CPU。MPS 不支持算子时回退 CPU，报告记录实际设备。CPU 输出与旧版兼容；可显式设置 video_device=cpu。
4. **提前检查和耗时报告**：人工标签/时段不足时，不开始视频处理；报告视频处理、拟合、评估耗时和缓存命中数。
5. **可解释的效果反馈**：保留漏判/误报数、同集旧版比较以及最多 12 个错例/纠正样本链接，明确当前版本是否生效。实战统计只采用人工标签，过滤模式也保存预测。
6. **无夜视降级**：原始水碗区域太暗时返回未知，暂停新候选触发；收尾片段 4 个采样帧中至少 3 个通过亮度检查才允许自动判断。候选录像不因未知状态写成负例。原始录像不增亮，弱光增强仅用于光照通过后的候选检测。

## 本机性能测量

2026-09-29，在当前 Apple Silicon Mac、PyTorch 2.14.0 上，用生成的 15 秒、10fps、640×480 视频测试；它是性能素材，不是猫咪准确率数据。模型权重已缓存，下载耗时不计入热运行。以下数据受机器负载、分辨率和编码影响。

| 测量项 | 结果 | 口径 |
| --- | ---: | --- |
| 旧视频抽帧 | 48.3 ms | 单次，150 帧转 RGB 后选 16 帧 |
| 新视频抽帧 | 16.9 ms | 单次，仅转换/保留 16 帧；相同采样输入 |
| S3D CPU | 181.3 ms/段 | 5 次热运行中位数 |
| S3D Apple MPS | 80.4 ms/段 | 5 次热运行中位数，约为 CPU 的 2.25 倍吞吐 |
| 特征缓存读取 | 0.139 ms/段 | 20 次读取中位数，不运行主干 |
| 分类头拟合 | 0.86 s | 一次，520×1024 合成特征、300 轮，含首次优化器准备 |

旧/新 CPU 特征在该素材上逐元素相同；MPS 相比 CPU 的最大绝对误差约 7.75e-7。这些结果说明减少重复特征提取很有价值，不证明实拍喝水召回率提高，也不保证任何用户设备达到同样速度。

## 开源小模型选择

| 模型 | 用途 | 在本项目中的取舍 |
| --- | --- | --- |
| [Ultralytics YOLO11n](https://github.com/ultralytics/ultralytics) | 约 2.6M 参数，COCO 预训练猫等常见物体检测 | 已作为新配置默认认猫模型；旧配置原值保留。实测能检测仓库猫咪封面中的猫，但单图不能证明泛化或喝水识别 |
| [PyTorchVideo X3D-XS](https://github.com/facebookresearch/pytorchvideo) | 约 3.8M 参数的轻量视频动作模型；官方还提供移动 CPU 优化版本 | 候选动作基座，需猫咪喝水标注适配与同集实测。更换后须重建特征并训练新头，不能套用旧 S3D 头 |
| [TensorFlow MoViNet-A0](https://github.com/tensorflow/models/tree/master/official/projects/movinet) | 面向移动端/流式动作分类，官方有约 12 MB checkpoint 与 TFLite 方案 | 适合后续低功耗设备部署；当前项目是 PyTorch，迁移成本较高，也没有直接验证的猫喝水专用效果 |

官方来源：[YOLO11 文档](https://github.com/ultralytics/ultralytics/blob/main/docs/en/models/yolo11.md)、[PyTorchVideo 模型表](https://github.com/facebookresearch/pytorchvideo/blob/main/docs/source/model_zoo.md)、[MoViNet README](https://github.com/tensorflow/models/blob/master/official/projects/movinet/README.md)。表中的参数量/大小来自各自官方资料，官方速度测试条件不相同，不直接横比。此次没有找到并验证一个可以直接承诺可靠猫咪喝水检测的专用小模型权重。

## 实际使用建议

固定水碗 ROI，照清猫嘴和水面，保留一个侧面或斜侧视角。无夜视时优先小夜灯或更换支持夜视的摄像头；纯黑场景无法靠多训几轮解决。补充“路过、闻水、低头不喝、舔毛”等难负例和真实舔水正例，比重复训练相同录像更有价值。

先保持影子模式，人工复核跨时段数据。在同一留出集上比较漏判/误报，再用未来新时段检验。当前亮度检查只是启发式，不保证看清猫嘴，也不记录历史监控中断时长；页面仍不能据零记录推断整夜没有喝水。更换动作基座、ROI 特征或连续短窗方案，应以同一真实数据基准决定，不以参数更少或版本更新作为效果证明。
