# 喝水区间建议格式

以 `prepare` 生成的 manifest 为依据，保存独立 JSON：

```json
{
  "clip": "clip_1234567890000.mp4",
  "fingerprint": "从 manifest 原样复制",
  "coverage": [[0, 30]],
  "segments": [[3.5, 8], [12, 18.5]],
  "unknown": [[20, 22]],
  "reason": "示例：两段可见持续舔水，其间抬头；20至22秒被遮挡",
  "model": "实际使用的Agent与视觉模型名称"
}
```

数值均为**原视频相对秒数**；开始小于结束，必须在录像时长以内。`coverage` 只填实际查看的范围；`segments` 和 `unknown` 必须在 coverage 内。没有明确动作可以提交空 segments，但这不改变“已确认喝水”的分类标签。返回的结果会把覆盖范围之外全部保留为 unknown，且把 unknown 从建议喝水区间中排除。

长视频每个窗口的时间戳已经带偏移，不能再次加上窗口起点。检查完所有窗口后，在同一个 JSON 中合并 coverage、segments、unknown 再提交，重叠区间由服务合并。也可提交部分视频建议，但必须在报告中说明范围；导入局部建议可能替换本页的完整草稿，用户须检查未覆盖区间后再保存。

返回 `id` 可在网页“素材任务”找到。素材指纹变化或录像被驳回后须重新获取信息；不要改指纹来绕过检查。旧视频只有总时长、没有动作边界时，不应把默认中间80%的轨道当成已识别结果。

若仅生成时间建议，不需查询水量或任何训练接口。`calibration` 只在用户需要水量估值时调用；`ml_per_second=null` 表示不能可靠换算，不能用部分已知时长去除完整周期耗水量。
